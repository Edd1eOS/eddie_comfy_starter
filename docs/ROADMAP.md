# 路线图

## Phase 0：架构骨架（已完成）

- 建立仓库规范、目录和安全边界。
- 定义图片/视频工作流的可复现要求。
- 设计 ComfyUI、Custom Nodes 与模型锁定清单格式。
- 明确 `setup`、`start`、`stop`、`doctor`、`update` 命令契约和验收标准。
- 评估官方 Desktop、comfy-cli、API v2 proxy/SDK 与 comfy-mcp 的复用边界。

## Phase 1：官方组件锁定与最小验证（当前）

- 锁定 ComfyUI Core 与选用官方组件的明确版本，评估 GPL/AGPL/MIT 组合影响。
- 选择一组最小图片工作流和最小视频工作流。
- 验证目标操作系统、GPU、显存和磁盘支持矩阵。
- 固定第一版上游、节点和模型清单。

## Phase 2：可运行包装

- 实现跨平台 `setup`、`start`、`stop`、`doctor`、`update`。
- 实现下载校验、配置解析、进程管理和环境诊断。
- 提供一个图片与一个视频端到端示例及烟测。
- 提供参数化高层工具，避免 Agent 直接拼装任意节点 ID。

## Phase 3：产品化

- 增加低显存与常规 GPU 预设。
- 完善节点冲突提示、模型缺失提示和故障排查。
- 支持安全升级、迁移、回滚和离线安装方案。
- 增加资产中心、运行历史、Agent 自动调整上限和付费节点确认。

## Phase 4：分发与质量

- 建立 CI、发布包、依赖清单、SBOM 和许可证归档。
- 验证全新机器安装、卸载和数据保留行为。
- 发布版本化文档和兼容性矩阵。

## MVP 完成标准

全新受支持环境可按文档完成安装并运行一个图片工作流；视频工作流可在声明的硬件档位运行；`doctor` 能定位常见依赖、节点、模型、端口和 GPU 问题；仓库中不存在模型、密钥、用户输入或生成输出。
